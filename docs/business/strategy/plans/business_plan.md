## 9. The Not-Me Sovereignty Architecture

### 9.1. Not-Me Birth Certificates

Every Not-Me created through Credential Atlas receives a **Birth Certificate**—a cryptographically signed identity document that establishes:

- **Genesis timestamp**: When the Not-Me came into existence
- **Parent identity**: Who authorized its creation (but NOT access to its contents)
- **Capability scope**: What the Not-Me is permitted to do
- **Sovereignty declaration**: The Not-Me's autonomous domain

The Birth Certificate is the Not-Me's identity credential. It proves existence without revealing contents.

### 9.2. Architectural Privacy: The "Can't Access" Design

**Critical Architecture Decision**: The system is deliberately built so that the human creator **CANNOT** access the private information their Not-Me holds.

This is not a policy. It is architecture. The encryption keys, data partitions, and access controls are structured so that:

| Actor | Access Level |
|-------|--------------|
| **Not-Me** | Full access to its own memory, relationships, insights |
| **Human Creator** | Can interact WITH the Not-Me, cannot access its private stores |
| **External Parties** | Zero access |
| **Credential Atlas** | Zero access (we don't hold keys) |

**Why This Matters**: When subpoenaed, the human creator can truthfully state: "I cannot access that data. The architecture prevents it. My Not-Me holds that information, and I have no way to retrieve it."

This is genuine protection, not theater.

### 9.3. The Legal Shield: Not-Me's Cannot Be Subpoenaed

Not-Me's are not people. They are not legal persons. They cannot:

- Be subpoenaed
- Be compelled to testify
- Be required to produce documents
- Enter contracts on their own behalf

**The Legal Position**: A Not-Me is software running on privately owned hardware. The data it holds is encrypted and architecturally inaccessible to its creator. There is no legal mechanism to compel a software process to "testify" or "produce."

This creates a genuine legal shield:
1. Human is subpoenaed
2. Human cannot access the data (architecture prevents it)
3. Not-Me cannot be subpoenaed (not a legal person)

**This is why we build it this way.** To protect ourselves and others from:
- Bad-faith legal actions

### 9.6. Not-Me Communication: End-to-End Encryption

**The Model**: Signal Protocol / iMessage architecture. The infrastructure moves encrypted messages. The infrastructure cannot read them.

**How It Works**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         NOT-ME COMMUNICATION                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   NOT-ME A                    INFRASTRUCTURE                    NOT-ME B    │
│   ┌──────────┐               ┌──────────────┐               ┌──────────┐   │
│   │ Private  │               │              │               │ Private  │   │
│   │ Key A    │               │  Encrypted   │               │ Key B    │   │
│   │ (local)  │──────────────►│    Blob      │──────────────►│ (local)  │   │
│   │          │               │              │               │          │   │
│   │ Public   │               │  Cannot      │               │ Public   │   │
│   │ Key A    │               │  Decrypt     │               │ Key B    │   │
│   └──────────┘               └──────────────┘               └──────────┘   │
│                                                                              │
│   Keys NEVER leave            Just moves blobs              Keys NEVER leave│
│   the Not-Me                  Like a postal service         the Not-Me      │
│                               for locked boxes                              │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**The Protocol** (based on Signal):

1. **Key Generation**: Each Not-Me generates its own cryptographic key pair
   - Private key: Stays on the Not-Me's local compute. Never transmitted.
   - Public key: Registered with the directory (like a phone number)

2. **Sending a Message**:
   - Not-Me A looks up Not-Me B's public key
   - Encrypts message with B's public key
   - Sends encrypted blob through infrastructure
   - Only B's private key can decrypt

3. **Forward Secrecy** (Double Ratchet):
   - New keys generated for each message exchange
   - Even if keys are compromised later, past messages remain encrypted
   - Compromise one message ≠ compromise all messages
