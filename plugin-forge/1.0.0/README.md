# Plugin Forge

The plugin that makes plugins — through THE LOOP (ALPHA:OMEGA), THE FURNACE (TRUTH:MEANING:CARE), THE MOLT, and THE TRACE.

## Installation

```
claude plugins add plugin-forge
```

## What It Does

Plugin Forge is a recursive plugin organism. It metabolizes your ecosystem through THE FURNACE — perceiving what IS (TRUTH), extracting what matters (MEANING), and forging what's needed (CARE). Every plugin it creates feeds back into THE LOOP. Each cycle's OMEGA becomes the next cycle's ALPHA. The chain grows organically based on actual usage, not theoretical planning.

Every plugin it forges emits cognitive traces — WORK.md (what was produced), TRACE.md (how it thought), and FILTER.md (what was signal vs noise). These traces make each cycle better than the last. The AGENT layer — the thinking that happens between input and output — is no longer discarded. It's persisted, consumed, and compounded.

### THE LOOP (ALPHA:OMEGA)

```
ALPHA (what IS + traces) → TRUTH:MEANING:CARE → OMEGA (what it BECOMES + new traces)
     ↑                                                │
     └──── OMEGA + traces become next ALPHA ──────────┘
```

Every plugin you forge changes the ecosystem state. That new state reveals the next gap. That gap becomes the next plugin. The traces compound. The loop never ends — it molts.

### The Three-Output Trace Protocol

Every plugin forged by Plugin Forge emits three files per operation:

```
trace/
├── WORK.md    ← what was produced (the deliverable)
├── TRACE.md   ← how it thought (decisions, attention, confidence, surprise)
└── FILTER.md  ← what was signal vs noise vs emerged insights
```

Previous traces feed the next cycle. TRACE tells the next agent how the last one thought. FILTER tells it what was noise. WORK tells it what was found. No separate training pipeline — the feedback loop IS the training loop.

### The Law of Surplus Value

**Output = Input + Revelation.** Every plugin must produce more than it consumes. A plugin that merely transforms without adding insight is entropic. Plugin Forge checks for surplus value at every step and flags entropic recommendations.

### Two Creation Modes

**Wizard Mode** — THE FORGE PROCESS: SEE → EXTERNALIZE → MELT DOWN → FORGE → IMPLEMENT → COMMIT → UPDATE LAW → CRYSTALLIZE. Interactive, thorough, scar-aware, trace-emitting.

**Scaffold Mode** — Fast template-based creation. Pick a starter template, get a complete directory structure with HOLD:AGENT:HOLD architecture and trace protocol baked in.

## The Framework Patterns

Plugin Forge embodies these patterns from THE_FRAMEWORK:

- **HOLD:AGENT:HOLD** — Every plugin, command, and skill follows Input → Transform → Output at every scale
- **THE LOOP (ALPHA:OMEGA)** — Each cycle's output + traces become the next cycle's input
- **THE FURNACE (TRUTH:MEANING:CARE)** — The metabolic process: perceive, extract meaning, forge with care
- **THE MOLT** — Plugins transform rather than just update; the ecosystem evolves through molting
- **THE TRACE** — The AGENT layer (cognition between input and output) is persisted as WORK + TRACE + FILTER
- **THE GRAMMAR** — Hyphens for collaborative names, underscores for infrastructure, colons for core concepts
- **Law of Surplus Value** — Output must exceed Input plus Revelation; entropic plugins are flagged
- **DNA Inheritance** — New plugins inherit capabilities from existing ones; don't reinvent, specialize
- **Scar-Aware Design** — Enforcement rules and failure patterns are compressed wisdom, not bureaucracy
- **Scale Invariance** — The same patterns apply from a single function to the entire ecosystem

## How It Creates Plugins

Every plugin follows the exact Cowork specification with HOLD:AGENT:HOLD + trace protocol at every level:

```
plugin-name/VERSION/
├── .claude-plugin/plugin.json    # DNA marker (identity)
├── .mcp.json                     # MEMBRANE (external connections)
├── README.md                     # PERCEPTION (how others see it)
├── CONNECTORS.md                 # BOUNDARY (what's connected)
├── commands/                     # CARE-EXTERNAL (user-facing actions)
│   └── command.md                # Each: INPUT HOLD → AGENT → OUTPUT HOLD → TRACE
└── skills/                       # METABOLISM (internal knowledge)
    └── skill-name/
        ├── SKILL.md              # Metabolic instructions + trace awareness
        └── references/           # MEMORY (deep knowledge on demand)
```

Runtime output:
```
trace/                            # COGNITIVE TRACE (the AGENT layer persisted)
├── WORK_[operation]_[ts].md      # What was produced
├── TRACE_[operation]_[ts].md     # How it thought
└── FILTER_[operation]_[ts].md    # Signal vs noise vs emerged
```

Plugins are packaged as `.plugin` files for direct installation in Cowork.
